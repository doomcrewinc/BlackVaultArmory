# Item Categories Phase 3 — NFA Paperwork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record the paperwork behind an NFA item — how it transferred, its control number,
approval date, tax paid and registered owner — on firearms and on suppressors, with the fields
appearing only where they apply and cleared server-side when they stop applying.

**Architecture:** One normalizer owns the whole field group per model, so every write path agrees
and no form can leave a stale stamp behind. A firearm's group is gated by `nfaClass`; an
accessory's by `type === "SUPPRESSOR"`, since accessories have no class column. The export gains
the class and paperwork columns, and the control number is treated as sensitive — gated behind
the same option that gates serial numbers.

**Tech Stack:** Next.js 16.1.6 App Router, Prisma 5.22 (one base schema, both providers),
Tailwind, vitest (`environment: "node"`).

**Spec:** `docs/superpowers/specs/2026-09-22-item-categories-design.md` — Phase 3 of six.

## Global Constraints

Each of these was paid for in phases 1 and 2.

- **`null` semantics depend on the column.** For a nullable column an explicit `null` in a write
  body clears it. For a `NOT NULL DEFAULT` column, `null` is treated exactly like an absent key
  and the stored value is preserved. A body that omits a field never changes that field.
- **Clearing is server-side, never merely hidden in a form.** A record must not keep a stamp
  date it no longer claims, however the write arrives — form, curl, or restore.
- **No `Promise.all` over Prisma queries** (SQLite `connection_limit=1`; a pool timeout raises
  the app's full-screen outage notice). Six routes run sequentially; follow them.
- **These routes expose PUT, not PATCH.**
- **Route tests assert on the arguments handed to the mocked Prisma call.** A helper test proves
  nothing about the wiring: in phase 1, 286 tests passed while a deleted `where` clause would
  have shown every section the whole vault.
- **State plainly, per test, whether it fails against the pre-fix code.** "Verified once by
  hand" and "guarded against regression" are different claims.
- **`whereForX(...) ?? undefined` is forbidden** — it turns "matches nothing here" into "match
  everything". That motif caused two live bugs across phases 1 and 2.
- **Adding a value to an enum breaks every `Record<Enum, …>` map**, and only `tsc` catches it.
- **`truncate` plus `flex` on one element hides its siblings**; truncating text gets its own
  `truncate min-w-0` element with siblings `shrink-0` outside it.
- **`react-hooks/set-state-in-effect` is an ESLint ERROR here.**
- **Never hand-edit `prisma/postgres/schema.prisma` or `prisma/sqlite/schema.prisma`** — they are
  generated by `npm run gen:schemas`. The Postgres `0_init` baseline is regenerated in place per
  `CONTRIBUTING.md` "Changing the schema"; that is only safe while no tagged release has shipped
  Postgres, which the file explains.
- **Dates are date-only.** Use `toDateOnlyUTC` on write and `toISODate` / `formatDateOnly` for
  display — never a local-timezone `new Date().toISOString()` detour, which shifts by a day.
- **Run `npx prettier --write` only on files already prettier-clean** — check each first. Many
  export and form files are dirty at baseline; match their style by hand.
- Verification, with real numbers reported: `npx tsc --noEmit -p .` (ZERO errors outside
  `*.test.ts`; ~16 pre-existing inside them are the baseline), `npm test` (currently **379 across
  40 files**), `npm run lint` (**0 errors**, 16 pre-existing warnings), `npm run build` once per
  task, and `bash scripts/check-migration-drift.sh` for anything touching `prisma/`.
- Accent `#00C2FF`, error `#E53935`, success `#00C853`; dark tokens `text-vault-text`,
  `bg-vault-surface`, `border-vault-border`, `text-vault-text-muted`. `—` for null values.
- Every page checked at 390px before a task is called done.

**Explicitly NOT in this phase:** the `Supply` and `Kit` models, expiry, armor fields, the
Preparedness group, gear categories beyond knives and cases, and a cross-model "all my NFA items"
view. Searching by control number is also out — the spec's phase 3 is columns, the conditional
form, and export columns.

## Task 1: The transfer-method enum and the clearing rules

**Files:** Modify `src/lib/types.ts`, `src/lib/nfa.ts`, `src/lib/nfa.test.ts`

**Interfaces:**
- Consumes: `NFA_CLASSES`, `MG_REGISTRIES`, `DEFAULT_NFA_CLASS` (already in `types.ts`).
- Produces:
  - `NFA_TRANSFER_METHODS = ["FORM_1","FORM_3","FORM_4","FORM_4473","OTHER"]`,
    `NfaTransferMethod`, `NFA_TRANSFER_METHOD_LABELS`
  - `type NfaPaperwork = { nfaTransferMethod: NfaTransferMethod | null; nfaControlNumber: string | null; nfaApprovalDate: Date | null; nfaTaxPaid: number | null; nfaRegisteredTo: string | null }`
  - `normalizeFirearmNfaFields(input): { nfaClass: NfaClass; mgRegistry: MgRegistry | null } & NfaPaperwork`
  - `normalizeAccessoryNfaFields(type: unknown, input): NfaPaperwork`

**The rules, which are the whole point of this task:**

1. A firearm with `nfaClass === "NONE"` has **no** paperwork: the whole group and `mgRegistry`
   are null. Dropping the class must not leave a stamp number behind.
2. `mgRegistry` survives only on `MACHINE_GUN` (already true; keep it).
3. `nfaTransferMethod === "FORM_4473"` means the item transferred as an ordinary firearm, so
   there is **no stamp**: `nfaControlNumber`, `nfaApprovalDate` and `nfaTaxPaid` are null.
   `nfaRegisteredTo` survives — someone still owns it.
4. An accessory's group applies only when `type === "SUPPRESSOR"`; any other type clears it.
   Accessories have no class column, so type is the gate.
5. Unknown enum values fall back rather than storing: an unrecognised method is `null`.
6. `nfaTaxPaid` is a non-negative number or null; a blank string is null, not `0`
   (`Number("")` is `0` — this bug has already shipped twice in this repo).

```ts
import { normalizeAccessoryNfaFields, normalizeFirearmNfaFields } from "./nfa";

const FULL = {
  nfaClass: "SBR",
  mgRegistry: "TRANSFERABLE",
  nfaTransferMethod: "FORM_4",
  nfaControlNumber: "12345",
  nfaApprovalDate: "2024-03-12",
  nfaTaxPaid: 200,
  nfaRegisteredTo: "Doe Family Trust",

describe("normalizeFirearmNfaFields", () => {
  it("keeps a full Form 4 record on an SBR, minus the registry", () => {
    const result = normalizeFirearmNfaFields(FULL);
    expect(result.nfaClass).toBe("SBR");
    expect(result.mgRegistry).toBeNull(); // only machine guns
    expect(result.nfaTransferMethod).toBe("FORM_4");
    expect(result.nfaControlNumber).toBe("12345");
    expect(result.nfaTaxPaid).toBe(200);
    expect(result.nfaRegisteredTo).toBe("Doe Family Trust");
    expect(result.nfaApprovalDate?.toISOString().slice(0, 10)).toBe("2024-03-12");
  });

  it("keeps the registry on a machine gun", () => {
    const result = normalizeFirearmNfaFields({ ...FULL, nfaClass: "MACHINE_GUN" });
    expect(result.mgRegistry).toBe("TRANSFERABLE");
  });

  it("clears the ENTIRE group when the class drops to NONE", () => {
    const result = normalizeFirearmNfaFields({ ...FULL, nfaClass: "NONE" });
    expect(result).toEqual({
      nfaClass: "NONE",
      mgRegistry: null,
      nfaTransferMethod: null,
      nfaControlNumber: null,
      nfaApprovalDate: null,
      nfaTaxPaid: null,
      nfaRegisteredTo: null,
    });
  });

  it("clears the stamp fields on a 4473 transfer but keeps the owner", () => {
    const result = normalizeFirearmNfaFields({ ...FULL, nfaTransferMethod: "FORM_4473" });
    expect(result.nfaTransferMethod).toBe("FORM_4473");
    expect(result.nfaControlNumber).toBeNull();
    expect(result.nfaApprovalDate).toBeNull();
    expect(result.nfaTaxPaid).toBeNull();
    expect(result.nfaRegisteredTo).toBe("Doe Family Trust");
  });

  it("rejects an unknown method rather than storing it", () => {
    expect(normalizeFirearmNfaFields({ ...FULL, nfaTransferMethod: "FORM_9" }).nfaTransferMethod)
      .toBeNull();
  });

  it("trims and upper-cases the method, and trims the text fields", () => {
    const result = normalizeFirearmNfaFields({
      ...FULL,
      nfaTransferMethod: " form_1 ",
      nfaControlNumber: "  A-77  ",
      nfaRegisteredTo: "  Trust  ",
    });
    expect(result.nfaTransferMethod).toBe("FORM_1");
    expect(result.nfaControlNumber).toBe("A-77");
    expect(result.nfaRegisteredTo).toBe("Trust");
  });

  it("stores a blank tax as null, not zero", () => {
    expect(normalizeFirearmNfaFields({ ...FULL, nfaTaxPaid: "" }).nfaTaxPaid).toBeNull();
    expect(normalizeFirearmNfaFields({ ...FULL, nfaTaxPaid: "200" }).nfaTaxPaid).toBe(200);
    expect(normalizeFirearmNfaFields({ ...FULL, nfaTaxPaid: -5 }).nfaTaxPaid).toBeNull();
  });

  it("stores a blank control number and owner as null, not empty strings", () => {
    const result = normalizeFirearmNfaFields({ ...FULL, nfaControlNumber: "  ", nfaRegisteredTo: "" });
    expect(result.nfaControlNumber).toBeNull();
    expect(result.nfaRegisteredTo).toBeNull();
  });

  it("refuses a malformed approval date rather than guessing", () => {
    expect(normalizeFirearmNfaFields({ ...FULL, nfaApprovalDate: "not-a-date" }).nfaApprovalDate)
      .toBeNull();
  });
});

describe("normalizeAccessoryNfaFields", () => {
  it("keeps the group on a suppressor", () => {
    const result = normalizeAccessoryNfaFields("SUPPRESSOR", FULL);
    expect(result.nfaTransferMethod).toBe("FORM_4");
    expect(result.nfaControlNumber).toBe("12345");
  });

  it("clears the group on any other type", () => {
    for (const type of ["OPTIC", "MAGAZINE", "BARREL", "", "ZZ_JUNK"]) {
      expect(normalizeAccessoryNfaFields(type, FULL), `type ${type}`).toEqual({
        nfaTransferMethod: null,
        nfaControlNumber: null,
        nfaApprovalDate: null,
        nfaTaxPaid: null,
        nfaRegisteredTo: null,
      });
    }
  });

  it("applies the 4473 rule on a suppressor too", () => {
    const result = normalizeAccessoryNfaFields("SUPPRESSOR", {
      ...FULL,
      nfaTransferMethod: "FORM_4473",
    });
    expect(result.nfaControlNumber).toBeNull();
    expect(result.nfaRegisteredTo).toBe("Doe Family Trust");
  });
});
```

```bash
npm test && npm run lint && npx tsc --noEmit -p . && npm run build
bash scripts/check-migration-drift.sh
```

Then, with the dev server running, at desktop and 390px:

1. A documented SBR round-trips: create, display, edit one unrelated field, paperwork intact.
2. Dropping its class to `NONE` clears the whole group, verified through the API.
3. Switching to 4473 clears the stamp fields and keeps the owner.
4. A suppressor's paperwork clears when its type changes away from `SUPPRESSOR`.
5. The export reports the SBR as an SBR, and hides its control number when serials are excluded.
6. Backup, delete the firearm, restore: the paperwork returns (the registry is row-generic, so
   this should need no new code — confirm it, do not assume it).
7. `/vault`, `/accessories`, `/gear`, `/builds` and the configurator behave as before.
