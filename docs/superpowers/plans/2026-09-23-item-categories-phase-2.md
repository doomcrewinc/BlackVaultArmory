# Item Categories Phase 2 — Gear Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `Gear` model for standalone kit that never mounts on a firearm — knives and cases —
with full CRUD, its own sections, and correct participation in documents, backup/restore,
search and the full-armory export.

**Architecture:** `Gear` is a peer of `Accessory`, not a subtype: no build slots, no round
count, no battery. The category registry from Phase 1 gains a third source (`"gear"`), so the
existing `/gear/[slug]` route serves both accessory-backed and gear-backed sections by
branching on the section's source. Everything that enumerates models — the backup registry,
search, the export — gains `Gear` explicitly, each guarded by a test.

**Tech Stack:** Next.js 16.1.6 App Router, Prisma 5.22 (one base schema generating both
providers), Tailwind, vitest (`environment: "node"`), lucide-react.

**Spec:** `docs/superpowers/specs/2026-09-22-item-categories-design.md` — Phase 2 of six.

## Global Constraints

Every one of these was learned the hard way in Phase 1. They bind every task.

- **Catch-alls by negation, never allowlists.** A category value nobody planned for must land
  in exactly one section, not zero. `src/lib/categories.ts` already does this for firearm
  platform, firearm class and accessory type; gear categories must join that property, and the
  exhaustiveness test must cover junk, empty-string and wrong-case values — not just the enum.
- **`null` semantics depend on the column.** For a nullable column, an explicit `null` in a
  write body clears it. For a `NOT NULL DEFAULT` column, `null` has no "cleared" state, so an
  explicit `null` is treated exactly like an absent key and the stored value is preserved. A
  write body that omits a field never changes that field.
- **Quantity never resets.** `normalizeQuantity(value, existing.quantity)` on update — a
  present-but-malformed value (an emptied number input posts `""`) must preserve the stored
  value, not fall back to 1.
- **No `Promise.all` over Prisma queries.** SQLite installs run with `connection_limit=1`;
  concurrent queries contend for one connection and a `pool_timeout` raises the app's
  full-screen outage notice. Six existing routes run sequentially and
  `src/app/api/backup/route.test.ts` pins `maxInFlight === 1`. Follow that.
- **These routes expose PUT, not PATCH.** Match the existing accessory and firearm routes.
- **Route-level tests assert on the arguments handed to the mocked Prisma call.** A test that
  only exercises a helper proves nothing about the wiring: in Phase 1, 286 tests passed while a
  deleted `where` clause would have shown every section the whole vault.
- **Verification is five commands:** `npx tsc --noEmit -p .` (ZERO errors outside `*.test.ts`;
  ~16 pre-existing errors inside test files are the baseline), `npm test`, `npm run lint`
  (**0 errors**), `npm run build` once per task, and `bash scripts/check-migration-drift.sh`
  for any task touching `prisma/`.
- **`react-hooks/set-state-in-effect` is an ESLint ERROR here.** Never call setState
  synchronously in a `useEffect` body; use a lazy `useState` initializer for browser-only
  values.
- **Adding a value to an enum breaks every `Record<Enum, …>` map** and only `tsc` catches it.
- **`truncate` plus `flex` on one element hides its siblings** — `text-overflow: ellipsis` has
  no effect on a flex container. Truncating text gets its own `truncate min-w-0` element, with
  siblings `shrink-0` outside it.
- **Never hand-edit `prisma/postgres/schema.prisma` or `prisma/sqlite/schema.prisma`** — they
  are generated by `npm run gen:schemas` from `prisma/schema.base.prisma`.
- Run `npx prettier --write` only on files you actually touch. `CONTRIBUTING.md` and
  `src/app/accessories/[id]/page.tsx` are not prettier-clean at baseline; leave them alone.
- Accent `#00C2FF`, error `#E53935`, success `#00C853`, dark-theme tokens (`text-vault-text`,
  `bg-vault-surface`, `border-vault-border`, `text-vault-text-muted`).
- Every page checked at 390px before a task is called done.

**Explicitly NOT in this phase** (later phases; their absence is correct, not a gap):
`expirationDate` and expiry badges, `protectionLevel` / `armorSize`, the gear categories beyond
`KNIFE` and `CASE`, the `Supply` model, the Preparedness nav group, `Kit` / `KitItem`.

```ts
/**
 * Standalone kit: things you own that never mount on a firearm. Phase 2 ships
 * knives and cases; later phases add armor, medical, shelter and the rest, so
 * anything reading these values must tolerate a category it has not seen.
 */
export const GEAR_CATEGORIES = ["KNIFE", "CASE"] as const;

export type GearCategory = (typeof GEAR_CATEGORIES)[number];

export const GEAR_CATEGORY_LABELS: Record<GearCategory, string> = {
  KNIFE: "Knife",
  CASE: "Case",
};

export const DEFAULT_GEAR_CATEGORY: GearCategory = "KNIFE";

/**
 * A write path never stores a category outside the enum. Unrecognised input
 * falls back rather than erroring, matching how the firearm class and accessory
 * quantity normalizers behave.
 */
export function normalizeGearCategory(value: unknown): GearCategory {
  if (typeof value !== "string") return DEFAULT_GEAR_CATEGORY;
  const candidate = value.trim().toUpperCase();
  return (GEAR_CATEGORIES as readonly string[]).includes(candidate)
    ? (candidate as GearCategory)
    : DEFAULT_GEAR_CATEGORY;
}
```

```prisma
// Standalone kit — never mounts on a firearm, so no build slots, no round
// count, no battery. A knife does not go in a build. Later phases add armor,
// medical and shelter categories plus expiry; see the item-categories spec.
model Gear {
  id              String     @id @default(cuid())
  name            String
  manufacturer    String?
  model           String?
  serialNumber    String?
  // GearCategory: KNIFE | CASE
  category        String
  // One record can stand for several identical items.
  quantity        Int        @default(1)
  purchasePrice   Float?
  currentValue    Float?
  acquisitionDate DateTime?
  storageLocation String?
  notes           String?
  imageUrl        String?
  imageSource     String?

  documents       Document[]

  createdAt       DateTime   @default(now())
  updatedAt       DateTime   @updatedAt

  @@index([category])
}
```


`onDelete: SetNull` matches how documents already survive a deleted firearm or accessory: the
